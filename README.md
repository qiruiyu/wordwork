# wordwork

`wordwork` 是面向小型课题组（老师 + 若干学生）的 **DOCX 协同审稿与版本管理** 软件。

成员继续用 Microsoft Word 或 WPS 编辑自己电脑上的 `.docx`，wordwork 负责分发工作
副本、收齐提交、展示真实差异、按修改片段取舍、处理多人冲突、发布定稿版本并集中备份。
系统不替换 Word，也不做实时共同编辑。

- 老师与学生只安装**桌面客户端**（Windows 托盘程序），不需要浏览器，也不需要懂接口。
- 课题组自己的一台服务器运行后台服务，文档只存在这台服务器上。

## 一、开发者：把后台跑起来

### 需要准备什么

- Python 3.12
- Node.js 20 或更高
- Rust（只有构建 Tauri 原生窗口才需要；只调界面可以先跳过）

### 一条命令启动

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-dev.ps1
```

脚本会检查工具链、安装 Python 与前端依赖、在 `127.0.0.1:8000` 启动后台服务，
等服务端就绪后再打开 Tauri 桌面窗口。常用开关：

| 开关 | 作用 |
| --- | --- |
| `-SkipInstall` | 依赖已装好，直接启动 |
| `-ServerOnly` | 只启动后台服务 |
| `-WebOnly` | 只启动浏览器开发模式（`http://localhost:5173`） |
| `-ServerPort 8010` | 换一个端口 |
| `-ResetData` | 启动前清空本地开发数据（`.dev-data`） |

第一次启动，后台会自动创建三个演示账号，**首次登录会强制改密码**：

| 账号 | 角色 | 初始密码 |
| --- | --- | --- |
| `teacher` | 老师 | `wordwork-demo-change-me` |
| `student1` | 学生 | `wordwork-demo-change-me` |
| `student2` | 学生 | `wordwork-demo-change-me` |

> 这三个是首次启动时自动创建的演示账号，**第一次登录会被强制要求改密码**：
> 服务端在改密之前会拒绝所有其他接口（HTTP 428），界面上的改密窗口也关不掉，
> 只能改完或退出登录。老师给学生新建的账号同样默认需要改密。

客户端首次打开会让你填写服务器地址，本地开发填 `http://127.0.0.1:8000`。

### 手动启动（不想用脚本时）

```text
python -m venv .venv
.venv/Scripts/pip install -e packages/doc_engine -e "services/api[dev]"
.venv/Scripts/python -m uvicorn app.main:app --app-dir services/api --reload

cd apps/desktop
pnpm install
pnpm tauri dev      # 原生窗口；只想看界面用 pnpm dev
```

### 跑测试和构建

```text
.venv/Scripts/python -m pytest services/api/tests packages/doc_engine/tests
cd apps/desktop
pnpm typecheck
pnpm test
pnpm build
pnpm tauri build    # 产出 Windows 安装包
```

`pnpm test` 里有一组**真实服务器联调测试**，默认跳过。想跑的话先启动后台服务再执行：

```powershell
$env:WORDWORK_LIVE_API = 'http://127.0.0.1:8000'
pnpm test
```

这组测试会让桌面端使用的同一套客户端代码去真实建项目、传文档、发轮次、交稿件、
审阅、合并、发布和回滚，用来确认界面按钮背后真的改了服务器数据。

## 二、管理员：把这台私有服务器部署上线

部署形态有两种，按你的实际情况选一条：

| 你的情况 | 走哪条 |
| --- | --- |
| 有 Linux 服务器，也申请了域名 | **A. Docker + 域名** |
| 服务器就是一台常开的 Windows 台式机，没有域名，学生直接用 IP 访问 | **B. Windows 单机 + IP 直连** |

两条路学生用的都是同一个桌面客户端，都不需要浏览器。

### A. Linux 服务器 + 域名

服务器建议用一台只有课题组自己人能访问的 Linux VPS，通过 HTTPS 对外提供服务。

#### 1. 准备配置

把 `.env.example` 复制成 `.env`，逐项填写：

| 变量 | 说明 |
| --- | --- |
| `WORDWORK_DOMAIN` | 对外域名，例如 `docx.lab.example.cn` |
| `WORDWORK_DATA_DIR` | 数据目录，默认 `/data` |
| `WORDWORK_DATABASE_URL` | 数据库地址，默认落在数据目录里的 SQLite 文件 |
| `WORDWORK_MAX_UPLOAD_BYTES` | 单个文档上限，默认 100 MB |
| `WORDWORK_BOOTSTRAP_TEACHER` | 第一个老师账号的用户名 |
| `WORDWORK_BOOTSTRAP_PASSWORD` | 第一个老师账号的密码，**至少 12 位** |
| `WORDWORK_BOOTSTRAP_FORCE_CHANGE` | 默认 `1`，首次登录强制改密码 |
| `WORDWORK_SESSION_DAYS` | 登录有效期，默认 7 天 |
| `WORDWORK_DEV_ORIGINS` | 允许的开发地址白名单，**生产环境请留空** |
| `WORDWORK_ALLOWED_ORIGINS` | 额外的可信来源白名单，没有就留空 |

`WORDWORK_BOOTSTRAP_*` 只在数据库为空、第一次启动时生效；之后改这些值不会影响已有账号。

#### 2. 部署

1. 把域名解析到这台 VPS。
2. 在服务器上执行 `docker compose up -d --build`。
3. 确认 `https://你的域名/healthz` 返回 `{"status":"ok",...}`，并且 `engine_available` 为 `true`。
4. 用第一个老师账号登录客户端，**立刻按提示改掉初始密码**，然后在客户端里创建学生账号。

#### 3. 安全要求

- 对外只开 HTTPS。客户端的地址校验会拒绝公网明文 `http://`。
- 接口只接受客户端来源，不允许任意网页跨域调用。不要为了图省事把来源写成 `*`。
- 文档以内容哈希寻址存放，只保存在数据目录里。系统不会调用第三方文档接口，
  也不会去拉取 DOCX 里的外部链接。
- 只接收 `.docx`；宏文档 `.docm` 会被直接拒绝。
- 建议按 `scripts/backup.sh` 定期备份数据目录，并用 `scripts/restore.sh` 演练恢复。
- 登录连续失败会被限制频率；会话记录在数据库里，可以单独作废。

### B. Windows 台式机（无域名、IP 直连）

如果你的「服务器」就是自己这台常开的 Windows 台式机、也没有域名，走这条。三件事
先知道：

1. **没有域名就用自建 CA 签证书**，代价是**每台学生机要一次性安装一张根证书**
   （有效期约 10 年，装一次就行）；
2. **你自己的教师端填 `http://127.0.0.1:8000`**，不需要装证书——服务端只监听回环；
3. **对外默认用 8443 端口**，因为大陆家宽普遍封入站 80/443。

用管理员 PowerShell 跑：

```powershell
cd D:\tools\wordwork
powershell -ExecutionPolicy Bypass -File scripts\windows\install.ps1
```

脚本会自动装好 Python 依赖、Caddy 和 WinSW，生成随机管理员密码，
把 API 和 Caddy 注册成**开机自启的服务**，并放行端口。之后：
导出根证书发给学生用 `scripts\windows\export-ca.ps1`，备份用 `backup.ps1`，
诊断用 `diagnose.ps1`，卸载用 `uninstall.ps1`。

完整步骤（各平台装证书、备份恢复、搬家、故障排查、外网可达性怎么验证）见
**[Windows 部署手册](docs/DEPLOY-WINDOWS.md)**。

## 三、老师：安装并使用客户端

### 安装

1. 拿到管理员给你的安装文件（`wordwork_0.2.0_x64-setup.exe` 或 `.msi`）。
2. 双击安装，按提示下一步即可（只装给当前用户，不需要管理员权限）。
   也可以直接用免安装的 `wordwork.exe`。
3. 如果这是实验室统一发放的机器，Windows 可能提示来源不明，选择「更多信息 →
   仍要运行」即可。

### 第一次打开

1. **先装根证书（只有实验室自建的服务器需要）**：如果管理员给你的是 IP 加端口的地址
   （例如 `https://192.168.1.10:8443`），说明服务器是自建的，要先照管理员的说明
   把根证书装进本机，否则会提示证书不受信任。在服务器这台机器上用自己的客户端不用装。
2. 客户端会让你填 **服务器地址**，把管理员给你的地址填进去，例如
   `https://docx.lab.example.cn` 或 `https://192.168.1.10:8443`，然后点「连接」。
3. 用管理员给你的账号和密码登录。如果提示要改密码，请当场改成只有你自己知道的密码。

### 老师能做什么

- **建项目和账号**：新建项目，把学生的账号加进来（学生自己不用注册）。
- **上传初始文档**：把这一轮要审的 Word 文档传上去，作为这一轮的基准版本。
- **发起轮次**：创建轮次并发布，学生那边就能看到这一轮了。
- **看学生的修改**：每个学生交了以后，你可以逐条查看真实差异，**逐条选择接受或拒绝**，
  也可以整体接受或整体拒绝，然后「定稿」这一份提交。
- **处理多人冲突**：如果两个学生改了同一段，系统会拦下来、告诉你冲突在哪一段。
  你可以指定保留哪一方，或者自己把合并好的文档传上去。
- **发布定稿**：把这一轮的结果发布成新的正式版本，同时留一份带修订痕迹的对照稿。
- **看历史版本**：查看、下载任意历史版本；需要时可以把它恢复成当前版本。

### 一些注意事项

- 学生交上来的稿件不会被覆盖，每一份都原样留着。
- 你改过的判定会记录在案，可以随时回看。
- 发布结果是不可回退到「未发布」的，但可以随时恢复历史版本来达到类似效果。

## 四、学生：安装并使用客户端

### 安装

和老师一样：拿到安装文件，双击安装，或者直接用免安装的 `wordwork.exe`。

### 第一次打开

1. **先装根证书**：实验室的服务器是用 IP 地址访问的（例如
   `https://192.168.1.10:8443`），证书由服务器自己签发，所以要先把老师给你的
   `wordwork-root-ca.crt` 装进本机——**这一步只要做一次**。
   Windows 上双击它 → 安装证书 → 存储位置选「本地计算机」→ 将所有证书放入
   「受信任的根证书颁发机构」→ 完成。手机和 macOS 的步骤照老师给的说明做。
2. 填入管理员或老师给你的 **服务器地址**，点「连接」。
3. 用老师给你开的账号和密码登录。如果提示要改密码，请改成只有你自己知道的密码。

### 你要做的事

1. **看轮次**：首页会列出老师已经发布的审稿轮次。
2. **下载工作副本**：点「下载工作副本」，选一个你自己电脑上的位置保存。
3. **用 Word 或 WPS 改**：点「用系统 Word 打开」直接编辑，或者自己找到那个文件打开。
   改完记得保存并**关闭 Word**（客户端要确认文件已关闭才能上传）。
4. **提交**：回到客户端，点「选择文件并提交」，选你刚改好的那份文档，写一句版本说明
   （例如「补充了第三段的实验数据」），然后提交。
   如果这时网络不通，客户端会先把这次提交排进队列，等网络恢复自动补交。
5. **看别人的修改**：不必等自己提交，随时都可以查看自己和同伴这一轮的差异、版本说明与批注，
   也可以在讨论区发言。但这些只是阅读，你**不能替老师做接受或拒绝**。

### 关于文件，请注意

- **不要**在下载的工作副本上反复改又反复交，每次改动都请重新下载一份最新的工作副本再改，
  否则客户端会提示你的基础版本已经过期。
- 客户端不会覆盖你正在 Word 里打开的文件；如果提示文件被占用，请先关掉 Word。
- 上传过程中断会提示你重新提交，不会留下半份文件。
- 你只能看到自己参与的项目，别的项目看不到。

## 项目结构

- `apps/desktop`：Tauri 2 + React 桌面客户端。
- `services/api`：FastAPI 服务、SQLite 数据库、内容寻址文档存储。
- `packages/doc_engine`：不依赖 Word COM 的 OOXML 校验、差异与合并引擎。
- `deploy`：服务器部署配置。`deploy/windows` 下是 Windows 单机部署用的模板。
- `scripts`：开发启动脚本、备份恢复脚本、图标生成脚本；`scripts/windows` 是部署与运维脚本。
- `docs`：架构、安全、试用验收，以及 [Windows 部署手册](docs/DEPLOY-WINDOWS.md)。

## 能力边界

已经做到：

- 版本全程不可变，每次提交和发布都留档。
- 正文段落与表格单元格可以按修改片段审阅。
- 多人改不同段落时自动合并；改同一段落时显式冲突，由老师决定。
- 登录状态存在服务端数据库里，可以单独作废；密码用 PBKDF2 加盐保存。
- 工作副本、离线提交队列、文件占用检测、系统通知都在客户端本地完成。

暂时不做：

- 实时共同编辑、完整聊天、微信机器人、内置 Word 编辑器。
- 只接受未加密、不含宏、不超过 100 MB 的 `.docx`。
- 图片、公式、图表、域等复杂对象一律按高风险结构块处理，不做自动合并。

完整设计见 [架构说明](docs/ARCHITECTURE.md)，安全边界见
[安全说明](docs/SECURITY.md)，课题组试用步骤见 [试用清单](docs/PILOT.md)。

## 常见问题

**连不上服务器？**
先确认地址填对了（要带 `https://`，自建服务器还要带端口，例如
`https://192.168.1.10:8443`），再确认这台电脑能打开管理员给你的网址。
本地开发用的 `http://127.0.0.1:8000` 只在跑后台服务的同一台电脑上有效。

**提示证书不受信任、证书错误？**
实验室自建的服务器用的是自己签发的证书，需要先按
[Windows 部署手册](docs/DEPLOY-WINDOWS.md) 第三节把根证书装进本机。
注意要装进「**受信任的根证书颁发机构**」，装进「个人」是不管用的。

**在办公室能连上，回到家用外网就连不上？**
局域网和外网用的是两个不同的地址，别混用（见部署手册第四节）。
如果外网地址在别的网络上也连不上，多半是运营商那边的问题——家庭宽带很常见
「看着有公网 IP、其实是运营商大内网」或者封了入站端口。让管理员照部署手册
第八节验证一下，必要时改用内网穿透。

**为什么上传时提示基础版本已过期？**
老师在你下载之后又更新了这一轮的基准版本。重新下载一份工作副本，把改动挪过去再提交。

**为什么不能接受或拒绝修改？**
这是老师的权力。学生可以查看差异和批注，但不能替老师做决定。

**会不会把我 Word 里的文件弄坏？**
客户端只写你自己选择保存的那份工作副本，而且会先确认 Word 已经关闭该文件，
不会动你原来在别处的文档。
